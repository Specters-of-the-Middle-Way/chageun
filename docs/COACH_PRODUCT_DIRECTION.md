# DriveStep — 내 차 안의 개인 운전 코치

제품 방향 / 최종 목표 갱신: 2026-11-11 / 기존 세 장면의 구현 설명은 v0.5 기준

## 2026-11-11 공모전 범위 갱신

운영사무국의 11월 11일 회신에 따라 **ADAS SDK는 이번 공모전에서 사용 불가**다. 추가 API·비공개 자료·특수 권한 승인을 받아 구현한다는 전제는 두지 않는다. 공개 SDK의 시트·버클·차량 경고·위치·내비를 먼저 연결하고, 차량 카메라 원본·주변 객체·거리 기반 자동 상황 인식은 향후 계획으로 분리한다. 사진·녹화·웹캠 대체 입력 시연은 실제 차량 입력과 구분한다. [공모전 범위와 향후 계획](CONTEST_SCOPE.md), [최신 워크플로우](AI_AGENT_WORKFLOW.md#03-2026-11-11-운영사무국-회신에-따른-공모전-실행-범위)를 따른다.

아래 자동 주변 인식은 장기 제품 목표다. 공모전 구현 완료 범위는 아니다.

## 2026-11-10 사용자 확정 방향과 후속 작업 기준

차근의 최종 목표는 **운전자가 주변 상황을 매번 말하지 않아도, 앱이 차량 신호와 확보된 주변 인식 데이터를 받아 필요한 순간에 먼저 안내하는 운전 연수 튜터**다. 대표 장면은 좌측 차로 변경 의도가 생겼을 때 옆 차로의 차량 밀집·정지·접근 상태를 인식하고 초보 운전자에게 짧게 준비 방법을 안내하는 것이다. 사람 대신 차량을 조종하는 것이 아니라, 상황에 맞는 연수 안내가 목표다.

현재 OpenAI LLM 연결은 카메라·주변 객체 데이터 접근을 확보하기 전 **운전자의 말로 상황을 입력받아 대화와 코칭 흐름을 시험하는 임시 경로**다. 이 경로의 완성을 최종 자동 상황 인식의 완성으로 간주하지 않는다. 최종 자동 안내 경로는 외부 LLM API 없이도 동작하도록 설계한다. STT·LLM 대화는 필요할 때 질문하거나 복습하는 선택 기능으로 남길 수 있지만, 상황 감지의 필수 입력으로 만들지 않는다.

사용자가 제공한 [차로 변경 작업 지시서 원본](references/2026-11-10-lane-change-proposal.md)은 참고 제안으로 보관한다. 그 안의 역할 지정·구현 과업·수식은 검증된 SDK 명세나 구현 완료 기능이 아니다. 원본의 카메라 없는 혼잡도 추정안보다 이 절의 최신 사용자 목표를 우선한다.

## 자동 인식을 위한 설계 방향

```text
입력: 허용된 카메라 프레임 또는 OEM 주변 객체 데이터
    + 자차 방향지시등·속도·브레이크 + 내비의 회전 준비 정보
 → 차량 검출·추적·차로 구분·영상 품질과 관측 시점 확인
 → 대상 차로의 관측 상태 + 운전자 의도 + 현재 연수 단계
 → 조건별 코칭 규칙·음성 우선순위·반복 억제
 → Pleos TTS 자동 안내 → 조작 관측 → 정차 후 복습
```

이 흐름은 개발 목표이며 현재 연결 완료 상태가 아니다. 내비의 좌회전 예정은 좌측 차로 변경 의도와 구분한다. 화면 왼쪽의 차량을 곧바로 왼쪽 인접 차로 차량으로 분류하지 않는다. 카메라 설치 방향·보정·차로 경계·가림을 고려해야 한다. 상대 거리·접근 속도를 사용하려면 보정된 연속 관측 또는 검증된 OEM 객체 데이터가 필요하다. 단일 이미지나 검출 상자 크기로 진입 가능한 틈을 확정하지 않는다.

LLM 없이 차량 검출·추적 모델과 규칙 기반 코칭을 구성할 수 있다. VLM은 영상과 언어를 함께 다루는 모델이며, 언어 생성 모델을 포함하는 경우가 많다. 실시간 인식의 필수 요소로 정하지 않고 장면 설명·복습용 후보로 평가한다. 음성 문장은 검증한 안내문을 조건에 맞게 선택해 Pleos TTS로 출력할 수 있다.

| 구성 요소 | 확인 상태와 사용 방향 |
|---|---|
| Pleos Vehicle·NaviHelper·TTS | 공개 SDK 제공 확인. 현재 앱은 자차 신호·내비 연결·음성 안내를 일부 사용한다. 완성된 옆 차로 인식 기능을 제공한다는 뜻은 아니다. |
| `PRIVATE_CAR_SAFETY` | 사용자가 제공한 주최 측 회신은 개발 중 사용 가능, 출시 심사는 별도라고 안내한다. 현재 Vehicle 2.3.2의 `Safety.registerTelltales()`에 해당 권한 요구를 확인했다. 카메라 프레임 접근 권한으로 해석하지 않는다. |
| `LCA_LEFT/RIGHT` | SDK 상수 존재 확인. 정확한 신호 의미, 저속 발동 조건, 경고 없음과 감지 불가의 구분은 주최 측·대상 차량에서 확인해야 한다. |
| Pleos 카메라·주변 객체·VLM SDK | 확인한 공개 SDK 목록과 Vehicle 2.3.2에서 차량 영상·주변 객체·VLM을 앱에 제공하는 공개 경로는 확보하지 못했다. 공모전에서는 공개 경로가 없는 기능을 향후 계획으로 분리한다. |
| MediaPipe Object Detector | Android의 이미지·비디오·라이브 스트림 객체 검출 API 제공. 영상 확보 후 검출 프로토타입 후보이며 차로별 추적·거리 판정까지 자동 제공하는 완성 모듈은 아니다. |
| LiteRT / ONNX Runtime Mobile | Android 기기 내 모델 실행 도구. Pleos에서 사용할 ABI·메모리·GPU/NPU·발열·지연과 대상 모델을 따로 검증해야 한다. |
| LiteRT-LM + 이미지 입력 지원 모델 | Android Kotlin에서 이미지와 텍스트 입력 지원. 예로 Gemma 3n이 문서에 있다. Pleos 기본 탑재 VLM 또는 실시간 운전 판단 성능이 확인된 모델로 소개하지 않는다. |

## 첨부 작업 지시서의 검증과 보완

| 원본의 제안 | 후속 작업 기준 |
|---|---|
| 내비·자차 감속·브레이크·안전 경고를 35/35/30으로 합산한 혼잡도 % | 가중치와 70% 문턱의 근거가 없다. 내 차는 정체되어도 옆 차로는 흐를 수 있어, 이 입력만으로 목표 차로의 실측 혼잡도·진입 위험 확률을 산출할 수 없다. 검증 없이 사용자 지표로 적용하지 않는다. |
| Unknown 내비를 30점, 미설정 크루즈를 80 km/h로 대체 | 미관측 상태를 임의 점수로 채우지 않는다. 크루즈 목표 속도는 옆 차로 속도나 도로 기준 속도와 다르다. SDK 자차 속도를 우선하며 위치 차분은 저속 오차를 따로 검증한다. |
| 모든 안전 경고의 색·우선순위·횟수를 차로 혼잡으로 해석 | 경고 종류와 대상 방향을 분리한다. `warningCount` 필드 존재는 확인했지만 주변 차량 수·접근 빈도라는 의미는 확인하지 못했다. 경고가 없다고 빈 차로로 처리하지 않는다. |
| `CAR_BRAKE`, `CAR_DRIVING_MODE`, `CAR_TURN_SIGNAL` | 현재 Vehicle 2.3.2의 권한 상수에서 확인되지 않았다. 공식 대표 권한은 Brake·DrivingMode=`CAR_DRIVE`, TurnSignal=`CAR_LIGHTS`이며 세부 함수의 요구 권한을 확인한다. `FUSED_LOCATION`은 공식 가이드에 존재하지만 현재 앱에는 해당 SDK가 설치되어 있지 않다. |
| `TrafficCongestionType`와 점멸 상수 | `navi-data` 3.0.4에 `UNKNOWN/FAST/MODERATE/SLOW/HEAVY`가 존재한다. 원본의 단순 3단계 매핑과 현재 링크 수신 경로는 재검증해야 한다. Vehicle의 점멸 상수는 `BLINK`이며 `BLINKING`이 아니다. |
| 정차·저속이면 안내를 일괄 억제 | 사용자가 원하는 저속 정체 차로 변경 준비 상황과 충돌할 수 있다. 실차 사용 정책과 경고음 우선순위를 확인해 별도 설계한다. 지금 구현한 P·정차 검증 게이트는 그대로 유지한다. |
| 권한 실패 시 가상 신호로 자동 교체 | 실측 화면에서 가상 경고를 조용히 섞지 않는다. 실패는 `UNKNOWN/UNAVAILABLE`, 시연은 사용자가 선택한 별도 입력 출처로 표시한다. |
| `HYBRID` TTS로 변경 | 최종 목표에 필수인 변경이 아니다. 현재 검증한 Pleos ON_DEVICE STT·TTS를 유지한다. |

## 권한 확보 전 진행할 수 있는 순서

1. **입력 출처 분리:** 운전자 설명, SDK 경고, 시험 영상, 실제 차량 카메라를 분리하는 입력 계층을 설계한다. 각 관측에 시각·유효 기간·대상 방향·관측 품질을 붙인다.
2. **녹화 영상 기반 비전 검증:** 사용 가능한 시험 영상에서 차량 검출·추적과 차로 구분을 평가한다. 인접 차로 정체, 내 차로만 정체, 빠른 후측방 접근, 오토바이·가림, 야간·우천, 영상 중단을 포함한다. 영상 출처·동의·사용 범위도 확인한다. 이것은 실제 Pleos 카메라 연결 검증과 별개다.
3. **SDK 경고 수신 검증:** 권한·capability·신호 값·갱신 시점·연결 종료를 실험한다. 지원 없음·경고 꺼짐·센서 제한·오래된 값을 구분한다. 저속의 LCA 의미는 공식 답변과 대조한다.
4. **자동 안내 연결:** 검증된 관측 이벤트에 맞는 짧은 문장을 선택하고 Pleos TTS로 자동 출력한다. 차량 기본 경고와 내비 음성을 우선하며, 중단되거나 오래된 안내는 재생하지 않는다. 이 단계는 외부 LLM 키 없이 시험할 수 있다.
5. **실차 연결과 평가:** 영상 API/권한 또는 OEM 객체 데이터가 확보되면 실제 입력을 연결한다. 검출·누락·잘못된 차로 배정, 촬영부터 발화까지의 지연, 지속 실행 시 발열·메모리, 초보 운전자에게 도움이 되는지 검증한다. 그 전에는 실제 진입 허가나 실차 연수 대체 성능을 주장하지 않는다.

11월 11일 회신 이후에는 카메라 프레임·주변 객체를 추가 승인받는 절차를 공모전 선행 조건으로 두지 않는다. 해당 입력과 실시간 자동 주변 판단은 향후 계획으로 분리하고, 주행 중 사용은 공개 정책을 따른다. 모델을 APK에 넣을 수 있다는 사실만으로 이 데이터와 권한이 생기지는 않는다.

## 만들려는 경험

DriveStep은 문제를 풀어 운전 지식을 확인하는 시험 앱이 아니다. 장롱면허 운전자와 초보운전자가 **자신의 차를 직접 조작하면, 앱이 조작을 관찰하고 옆자리 강사처럼 짧고 다정하게 안내하는 차량용 연수 코치**다. 스마트폰을 꺼내지 않고 준비, 연습, 복습을 차 안에서 끝내는 것이 핵심이다.

현대자동차의 기본 탑재 기능으로 제공하는 것은 제안 목표다. 현재 개발 앱에 OEM 시스템 앱의 권한이 부여되었거나, 실차에서 도로 상황을 판단하는 기능이 구현되었다는 뜻은 아니다.

## 실제로 쓰는 세 장면

### 1. 출발 전: “내 차에 먼저 익숙해져요”

운전자는 정차한 차에서 시트·핸들·미러를 맞춘다. 코치는 “브레이크를 끝까지 밟았을 때 무릎이 조금 굽혀지는지 확인해 주세요”처럼 몸으로 확인할 행동을 안내한다. 키만으로 안전한 위치를 자동 확정하지 않는다. 운전자가 자세 확인을 마치면 방향지시등 레버의 위치와 조작법을 알려주고 직접 조작하도록 기다린다.

**현재:** 자세 가이드는 운전자가 직접 확인한다. 기본 홈의 레버·조향 실습은 정차·P 조건에서 SDK 신호에 따라 피드백한다. 에뮬레이터에서는 Virtual Console로 입력한 차량 신호를 받으며, 실차 조작 검증을 완료한 상태는 아니다.

### 2. 조작 실수: “괜찮아요. 이번에는 왼쪽으로 해볼까요?”

왼쪽 방향지시등 연습 중 오른쪽 신호가 들어오면 코치는 틀렸다는 점수부터 보여주기보다 지금 받은 신호와 다음 행동을 알려준다. 올바르게 조작하면 확인하고, 같은 실수가 반복되면 설명을 더 천천히 제공한다. 익숙해진 동작에는 안내를 줄이는 것이 제품 목표다.

**현재:** 조작 신호를 정해진 연습 목표와 비교하는 방식이다. 별도 정차 중 시뮬레이션에서는 가상 페달·기어·핸들을 연속 조작하며 출발·정지와 횡단보도 상황을 연습한다. 이 도로 모델은 **행동에 반응하는 튜터 대화 경험을 검증하는 프로토타입**이다. 실제 도로의 보행자나 차선을 감지하거나, 실차 연수를 대체할 수 있음을 검증한 모델은 아니다.

**다음 목표:** 허용된 실차 신호와 주행 중 앱 정책을 확인한 뒤, 운전 중 화면 조작을 요구하지 않는 짧은 코칭을 검증한다. 주변 인식 데이터가 없을 때는 “지금 끼어드세요” 또는 “핸들을 몇 도 돌리세요”처럼 공간의 안전성을 전제로 한 지시를 만들지 않는다.

### 3. 주행 후: “오늘 어려웠던 동작만 다시 해봐요”

운전이 끝나면 코치는 관찰한 조작과 반복 실수를 묶어 보여준다. 예를 들어 방향지시등 조작에서 자주 혼동했다면 다음 연습의 첫 안내를 해당 동작에 맞춘다. 평가의 기준은 다른 사람보다 빠르게 수행했는지가 아니라, **내가 어떤 동작을 스스로 해냈고 어디에서 도움이 필요했는지**다.

**제품 목표:** 준비 → 조건부 실차 코칭 → 내 실수 복습 → 항목별 안내 감소의 흐름을 연결한다. 단일 0~10 등급으로 실제 운전 능력을 단정하지 않고, 조작 이해·순서 수행·반복 실수·도움 없이 수행한 정도를 항목별로 구분한다. 신호로 확인할 수 없는 시선 확인이나 양보 판단은 자동 평가한 것처럼 표시하지 않는다. 개인별 장기 적응과 실제 주행 후 자동 복습의 전체 흐름은 후속 개발·검증 범위다.

## 현재 구현과 다음 검증의 경계

| 범위 | 상태와 확인할 내용 |
|---|---|
| 정차 중 조작 코칭 | v0.5 핵심. 레버·조향 신호에 반응하는 음성 피드백과 수동 자세 확인. 실차 지원 신호·정확도·지연은 추가 확인한다. |
| 가상 연속 주행 | v0.5 별도 프로토타입. 가상 페달·기어·핸들 조작과 코칭의 연결을 확인한다. 실제 차량 제어·물리 정확성·연수 효과의 검증 결과로 해석하지 않는다. |
| 주행 중 실차 코칭 | 앱 카테고리, 권한, 주행 제한, 내비·차량 경고와의 음성 우선순위를 확인한 뒤 제한된 환경에서 검증할 목표다. |
| 전방·차선·보행자·교행 공간 판단 | 현재 앱의 입력 데이터가 아니다. 일반 앱에 제공되는 API, 대상 차종, 권한, 데이터의 의미와 신뢰도를 먼저 확인해야 한다. |
| OEM 기본 탑재·개인별 성장 | 제안·확장 목표. 기본 탑재만으로 모든 시스템 권한을 사용할 수 있다고 가정하지 않는다. 관찰 가능한 항목부터 개인별 도움 수준을 검증한다. |

## 기술 근거와 미확인 사항

- **현재 공개 범위:** 최신 라이브 SDK 개요는 Vehicle·NaviHelper·STT·TTS·FusedLocation을 안내한다. Vehicle SDK는 차종별 `checkXXXCapabilities`와 필요한 권한 확인을 전제로 하며, 권한 사용은 Pleos App Market과 협의·승인된 범위여야 한다. [SDK 개요](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/), [Vehicle SDK 2.3.2 가이드](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/Vehicle/intro)
- **ADAS는 이번 공모전 사용 불가(11월 11일 회신 반영):** 과거 검색 색인에는 ADAS의 차선·주변 객체 구독 API가 남아 있지만, 확인일에 해당 [기존 ADAS API 주소](https://document.pleos.ai/en/api-reference/connect-sdk-pleos/Adas/adas/ai.pleos.playground.adas/adas/entry)는 Page Not Found였다. 현재 확보한 Vehicle 2.3.2 소스에도 영상 스트림·차선·주변 객체 목록 API를 확인하지 못했다. 과거 색인을 구현 가능 근거로 사용하지 않으며, 공모전 구현에 사용하지 않으며, 공모전 밖의 향후 연계는 별도로 정의한다.
- **주행 중 동작은 별도 조건:** DO(주행 중 사용을 고려한 설계)를 선언하더라도 `CarUxRestrictions`와 `ActiveRestrictions`에 맞게 기능을 제한해야 한다. 운전 코칭의 허용 범위를 확인해야 하며, 선언만으로 승인이 보장되지 않는다. [주행 제한 개발 가이드](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide), [앱 카테고리 정책](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/app-category)
- **카메라·시스템 권한:** 차량의 시스템 카메라는 일반 설치 앱이 접근할 수 없을 수 있다. OEM 앱의 화면에 영상이 보인다는 사실만으로 우리 앱의 영상 접근을 보장할 수 없다. 제공되지 않는 특수 차량 속성은 기술지원팀에 검토를 요청한다. [Android 시스템 카메라](https://source.android.com/docs/core/camera/system-cameras), [Pleos API 가용성](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/api-compatibility-availability)

이번 단계의 성공 기준은 “정답을 고르게 했는가”가 아니라 **사용자가 안내를 이해하고 조작했을 때, 코치가 관찰 가능한 신호에 근거해 적절한 순간에 반응하는가**다. 실차 연수 효과는 이후 별도의 사용자·차량 검증으로 확인한다.
