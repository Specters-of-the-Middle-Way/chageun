## 코드 위치와 재사용

- `journey/JourneyState`, `DriverJourneyView`, `PostureGuideView`: 기존 프로필·준비·재방문을 유지한다.
- `workflow/WorkflowModels`: 입력 품질·날씨·후보 경로·내비 접수·발화 중재 계약.
- `workflow/WorkflowCatalog`: D01~D18 과제와 출처가 명시된 가상 설명서.
- `workflow/ScenarioSession`, `ScenarioSurfaceView`: 독립 상태·가상 조작·그리기.
- `workflow/WorkflowView`: 날씨/학습/코스/조작/복습을 연결하며 준비 상태를 우회하지 않는다.
- `workflow/WorkflowStore`: 기존 저장소와 별개의 로컬 기록·중단 과제. 저장 시점마다 동의를 확인한다.
- `parking/ParkingSimulationSession`, `ParkingSimulatorView`, `ParkingSceneView`: 기존 물리 모델과 기록을 재사용해 4개 유형을 제공한다.
- `speech/TutorSpeechController`: 기존 기기 내 음성 출력·오디오 포커스·취소를 재사용한다. 새 동적 안내에는 WAV 대체가 있다고 표시하지 않는다.
- 기존 `lessoncoach`의 음성 연수와 명시적 외부 LLM 시험 모드는 유지했다. 새 날씨·코스·차량 기능은 OpenAI 키나 외부 전송 없이 실행한다.

## 제거·정리한 기능

- 주 화면에 도달할 수 없는 과거 `coachHome` 구성 함수를 제거했다.
- 일반 교육 메뉴의 기존 퀴즈/학습 자료 진입과 개발용 ‘상황 감지 변수’ 진입을 제거했다.
- SDK 화면의 중복 ‘성장 튜터로 돌아가기’ 진입을 제거했다.
- 프로필에 불필요하게 표시하던 데모 성별·인종 문구를 제거했다. 기록 동의나 기존 사용자 기록은 삭제하지 않았다.
- ‘운전 숙련도 평가 중’을 ‘미평가’로 바꿨다. 실제 평가 작업이 실행 중인 것처럼 표시하지 않는다.
- 기존 기초 조작·시뮬레이션 상태 모델과 과거 기록 저장소는 회귀와 재사용을 위해 유지했다.

## 실행

앱 상단 **준비와 연습** 또는 **출발 전 확인 → 연습 선택 → 준비와 연습**으로 연다.
날씨·가상 기능 학습은 정차 상태에서 준비 완료 전에도 이용할 수 있다. 가상 주행·주차를 시작하면 프로필·9개 자세·7개 출발 전 확인이 필요하다.

```bash
./scripts/build.sh --console=plain :app:assembleDebugAndroidTest
python3 simulation/test/runners/run_scenario_qa.py
# 한 대의 DriveStep_Pleos 에뮬레이터를 P·속도 0에 두고:
python3 scripts/verify-workflow.py --serial emulator-5554
```

동일 앱 실행 중 일시 정지는 기록 동의 없이도 운전 준비 재확인 후 명시적으로 이어갈 수 있다. 프로세스가 다시 만들어진 경우 저장된 중단 과제와 지점을 보여주고 **새 가상 시도**로 시작한다. 물리 좌표나 오래된 조작·음성을 자동 복원하지 않는다. 사용자 저장 거부 시 세션 내 연습만 제공한다.

## 남은 외부 의존성

실제 날씨 공급자·최신성 정책, 차종·연식·트림별 설명서 라이선스와 콘텐츠, 초보 코스용 실제 지도 특성·경로 후보, 실주행 백그라운드/코칭 허용 범위, 이중 주차 정의, 실차/전문가 검증은 미확정 또는 미연결이다. 시트·벨트·경고·위치·내비의 공개 SDK 연결은 아래 추가 구현으로 분리했다. ADAS 사용 불가는 확정이며 카메라·차선·주변 객체·거리 채널은 공개 경로 미확보로 [향후 계획](CONTEST_SCOPE.md)에 정리했다. 해당 기능을 지원한다고 가장하거나 실제 경고·제한을 우회하지 않는다.

이번 재검증은 TASK-02·04·07·09, TC-06·08~11·15~16·18·20~21·23~24를 중심으로 기존 회귀 검사를 함께 실행했다. 실제 데이터 공급자가 없는 영역은 위 대응표의 미연결 상태를 유지한다.

### 발견한 문제와 변경

- 코스의 유효시간을 조회 시에만 확인하던 문제를 수정했다. 후보 선택, 늦게 도착한 추천 응답 적용, 접수한 코스의 실제 시작 시점마다 15분 유효시간을 다시 확인한다. 만료된 접수는 해제하며 사용자가 `코스 다시 조회` 후 재선택할 수 있다.
- `InputEnvelope.effectiveValidity`로 최신성 판정을 모았다. 관측 시각·값·문맥이 없으면 `UNKNOWN`, 미래/음수 시각은 `ERROR`, 실제 유효시간 초과는 `STALE`로 구분한다. 거리의 잘못된 단위·음수·비유한 값은 오류로 보류하며 없는 값을 0으로 바꾸지 않는다.
- 앱 아이콘을 차량과 도로를 표현한 청록·흰색·민트 벡터로 교체했다. 기본/원형 런처와 단색 테마 리소스는 [앱 아이콘 구성](APP_ICON.md)을 참고한다.
