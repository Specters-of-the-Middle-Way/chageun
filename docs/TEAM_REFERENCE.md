## 1. 우리가 만들고 있는 것

면허는 있지만 실제 운전이 낯선 사람, 오랫동안 운전하지 않은 사람이 **설명을 듣고 → 직접 조작하고 → 상황에 맞는 도움을 받고 → 어려웠던 동작을 다시 연습하는** 차량용 운전 튜터입니다.

사용자가 원하는 것은 시험을 통과하는 것보다 “지금 무엇부터 해야 하는지 알겠다”, “실수해도 다음 행동을 안내받을 수 있다”는 경험입니다. 그래서 핵심 방향은 객관식 문제나 순위보다 **다정한 음성 안내와 직접 조작에 반응하는 연습**입니다.

| 구분 | 내용 |
|---|---|
| 장기 제품 목표 | 준비 → 허용된 실차 신호에 근거한 짧은 상황 코칭 → 정차 후 복습 → 항목별 도움 수준 조절 |
| 현재 구현 | 정차 중 SDK 조작 연습, 작성된 가상 도로에서의 직접 조작, 가상 입력에 반응하는 코치, 로컬 기록·회고 |
| 아직 확인하지 않은 성과 | 실차 주행 코칭의 효과, 운전 연수 대체 가능성, 실제 운전 숙련도 향상 |

**차량 앱이어야 하는 이유:** 해당 차량의 조작 신호를 받고 그 차의 조작법과 연습을 연결하는 것이 목표입니다. 현재의 가상 도로 시뮬레이션만으로는 스마트폰과의 차이가 충분하지 않습니다. 차량 앱의 필요성은 SDK 기반 조작 경험과 향후 승인된 실차 코칭을 연결하면서 검증해야 합니다.

현대자동차 공식 기본 탑재 앱이라는 뜻은 아닙니다. 기본 탑재는 제안 방향이며, 현재 앱은 우리가 개발한 프로토타입입니다. 앞서 논의한 카페리·렌터카·역사 콘텐츠는 현재 운전 튜터의 구현 범위에 포함하지 않습니다.

## 2. 가장 먼저 구분할 세 가지 입력

| 구분 | 입력이 들어오는 경로 | 현재 확인한 것 |
|---|---|---|
| **SDK 조작 연습** | 에뮬레이터 차량 콘솔 조작 → Pleos SDK / Android Automotive 신호 → 앱 | 방향지시등·조향 등의 신호 수신과 목표 동작 비교 |
| **상황 감지 검증 화면** | 화면에서 속도·방향지시·경고 등 가상 변수 입력 → 규칙 엔진 | 어떤 조건에서 코치가 반응하는지와 입력 근거 기록 |
| **운전자 시점 시뮬레이터** | 화면 속 깜빡이·미러·핸들·페달 → 자체 가상 주행 모델 | 도로·주변 차량의 움직임과 음성 코칭·회고 연결 |

SDK 경로를 실제로 사용했다는 것과 실제 자동차에서 시험했다는 것은 다릅니다. **현재 검증은 에뮬레이터 기준**입니다. 시뮬레이터의 가상 속도와 화면 속 차량은 실제 차량 상태를 변경하지 않습니다.

|---|---|---|

| 핸들 · 코치와 시작 | P·정지·신호를 확인하고 왼쪽·중앙·오른쪽·중앙 조작 | Pleos 조향 신호와 AAOS 기어·속도 활용 |

| 조작형 연수 체험 열기 | 가상 기어·페달·핸들로 출발·정지, 횡단보도 대기 연습 | 기존 가상 연수. 실제 도로의 신호·보행자를 인식하지 않음 |
| 상황 감지 변수 확인 · 개발용 | 속도 감소·증가·경고 상황을 만들고 반응 근거 확인 | 가상 입력 조합, 사건 저장, 입력 순서 재현 |
| 내 조작 기록 · 복습 | 이전 SDK 연습의 완료·중단과 수신 이벤트 확인 | 기기 내부 기록 |
| 기존 교통상식 학습 자료 | 기존 학습 콘텐츠 확인 | 보조 자료로 유지. 최신 핵심 시연은 직접 조작 중심 |

**주차 관련 현재 범위:** 주차 순서 안내와 기초 이해 자료, P·정차 상태의 기어·조향 신호 확인입니다. 후진하면서 실제 주차 공간을 계산하거나, 장애물과의 거리·주차 성공을 자동 판정하는 기능은 없습니다.

기존 성장 학습 화면에는 로컬 학습 점수·포인트와 **가상 참가자를 이용한 예시 순위**가 남아 있습니다. 실제 운전 실력을 평가하거나 다른 사용자와 연결한 순위가 아니며, 새 운전자 시점 시뮬레이터는 조작 회고를 중심으로 구성했습니다.

### 화면 구성

### 연습 흐름

```text
코스 선택 → 방향지시 → 해당 방향 미러 확인
                         ↓
                  옆 차가 가까우면 대기
                         ↓
핸들을 직접 움직여 목표 차로 진입 → 핸들 중앙 → 방향지시 끄기 → 회고
```

| 코스 | 배우는 행동 |
|---|---|
| 왼쪽 차로 변경 | 왼쪽 방향 알리기, 왼쪽 미러 확인, 조향 후 마무리 |
| 오른쪽 차로 변경 | 오른쪽 방향 알리기, 오른쪽 미러 확인, 조향 후 마무리 |
| 옆 차를 기다린 뒤 변경 | 옆 차량을 관찰하고, 핸들을 중앙에 두고 기다린 뒤 진행 |

옆 차량 코스에서는 설명을 천천히 읽어도 핵심 상황을 놓치지 않게, 미러 확인 전까지 옆 차가 같은 가상 속도로 움직입니다. 올바른 미러 확인 뒤 옆 차가 앞으로 이동합니다. 실제 교통 상황을 복원한 것이 아니라 작성된 교육용 시나리오입니다.

### 조작할 때 알아둘 점

| 조작 | 실제 앱의 동작 |
|---|---|
| 시작 | 화면 속 차량이 가상 속도 40km/h로 출발 |
| 가속·브레이크 | 누르는 동안 작동. 손을 떼면 현재 가상 속도 유지 |
| 핸들 슬라이더 | 왼쪽·오른쪽 입력으로 횡방향 이동. 손을 떼어도 값 유지 |
| 핸들 중앙 | 슬라이더 입력을 중앙으로 복귀 |
| 미러 보기 | 사용자가 확인했다는 버튼 입력. 시선 추적 아님 |
| 완료 | 목표 차로에서 중앙 조향과 신호 끄기까지 수행 |
| 가상 차량 겹침·도로 이탈 | 연습을 멈추고 회고. 자동으로 성공 처리하거나 재시작하지 않음 |

마우스 하나로도 조작 순서를 연습할 수 있도록 단순화했습니다. 이 모델의 속도·조향량·거리 수치를 실차의 핸들 회전 수나 제동거리로 환산해서 사용하지 않습니다.

### 코치는 언제 말하는가

반대 방향 신호, 신호·미러 확인 누락, 가까운 옆 차량, 급격한 속도 변화, 목표 차로 도달 등에 짧게 반응합니다. 예를 들어 “신호가 반대쪽이에요. 목표 방향으로 바꿔봐요” 또는 “옆에 가상 차량이 있어요. 핸들을 중앙에 두고 기다려요”처럼 다음 행동을 안내합니다.

음성은 **작성된 고정 문구와 규칙**에 근거합니다. 현재 LLM이 전방을 이해하거나 주행 지시를 만드는 구조는 아닙니다.

## 5. ‘상황이 오면 튜터가 반응한다’는 기능

사용자가 제안한 핵심은 깜빡이를 켠 채 속도가 급하게 줄거나 늘어나는 등 어려움의 징후가 있을 때 코치가 먼저 반응하는 것입니다. 현재는 이 판단 흐름을 **가상 입력으로 검증**하고 있습니다. 메뉴에서 자동으로 실주행 시뮬레이션 화면을 띄우는 기능까지 구현한 것은 아닙니다.

| 변수 | 현재 상황 코치에서의 역할 |
|---|---|
| 방향지시등 | 왼쪽·오른쪽·꺼짐·비상등·미확인 구분 |
| 속도와 관측 시각 | 최근 구간의 증가·감소 계산 |
| 차로 변경 경고 | 미확인·없음·좌·우·양쪽의 시험 입력 |
| 기어 | P·D·R·N·미확인 문맥 구분 |
| 브레이크·조향 | 입력 근거와 복습 자료. 이것만으로 실제 차로 변경 완료를 판정하지 않음 |
| 도로 문맥 | 직선·교차로·주차·미확인. 현재 내비 자동 분류가 아닌 수동 입력 |
| 차량 경고음 우선 조건 | 켜져 있으면 코치의 추가 발화를 억제하고 기록만 저장 |
| 출처·신호별 관측 시각 | 가상/SDK 구분, 오래된 신호·역순 입력 처리 |

**현재 규칙의 실험값:** 최근 3초 구간에서 최소 2초를 관측하고, 방향지시 중 속도 변화가 ±12km/h 이상인 경우 등을 처리합니다. 비교하는 두 속도가 모두 15km/h 미만이면 속도 기반 차로 변경 코칭을 억제합니다. 신호 유효시간은 1.5초, 발화 대기시간은 15초입니다. 같은 방향지시 시도에서 속도 안내를 반복하지 않으며 새 경고를 우선 처리합니다.

이 값은 법규나 제조사 기준이 아닙니다. 속도 변화만으로 운전자의 불안·미숙이나 안전한 진입 공간을 확정하지 않습니다. `SituationConfig`에서 값을 조정할 수 있으며, 사용자 검증을 거쳐야 합니다.

차로 변경 경고·차선 이탈 경고·후측방 충돌 경고는 실차에서 각각 의미를 확인해야 합니다. 현재 시험용 경고 변수가 있다는 이유로 해당 실차 API 연동이 완료된 것으로 설명하면 안 됩니다.

## 6. 음성·기록·중단 처리

| 항목 | 현재 구현 |
|---|---|
| 음성 | 한국어 TTS, 사용 불가 시 앱에 포함한 WAV 안내 |
| 음성 자산 | 전체 178개. v0.7 시뮬레이터 신규 문구 18개 포함 |
| SDK 방향지시등 기록 | SQLite에 연습 진행·완료·중단 및 이벤트 저장 |
| SDK 조향 기록 | 앱 내부 JSON 파일에 저장 |
| 상황·가상 주행 기록 | 별도 SharedPreferences에 저장. 각 기록군 최근 20회 보관 |
| 새 시뮬레이터 회고 | 수행 단계·코치 개입·완료 여부 등. 실제 운전 능력의 점수·순위 없음 |
| 앱 이탈·주행 제한 | 시뮬레이션 시간·입력·음성 중단, 복귀 후 명시적 이어하기 |
| 프로세스 재시작 | 회고와 선택 코스 유지, 진행 중이던 가상 주행을 자동 시작하지 않음 |
| 외부 전송 | 현재 기록 업로드 서버와 휴대폰 동기화 기능 없음 |

정차 사용 여부는 플랫폼의 `CarUxRestrictions`를 확인합니다. **P·속도 0은 에뮬레이터 시연 준비 조건**입니다. 앱이 P라는 문자만 보고 모든 상황에서 사용을 허용하는 방식은 아닙니다.

개발 시 주의할 기존 사례도 있습니다. SDK 방향지시등 조작 중 Pleos의 측면 카메라가 표시되면 Activity가 부분 일시정지될 수 있습니다. 새 시뮬레이터의 즉시 중지 처리가 기존 SDK 교정 음성까지 끊지 않도록 구분했습니다. 이 구분을 변경할 때는 양쪽 연습을 함께 확인해야 합니다.

## 7. 처음 실행하는 팀원을 위한 순서

### 필요한 환경

| 항목 | 프로젝트 기준 |
|---|---|
| 언어·화면 | Kotlin / Android View·Canvas |
| JDK | 17 |
| Gradle / Android Gradle Plugin | 8.10.2 / 8.8.2 |
| Kotlin 플러그인 | 2.0.0 |
| Android SDK | compileSdk 35 / targetSdk 34 / minSdk 28 |
| 차량 SDK | Vehicle 2.3.2 / `android.car` |
| 검증 환경 | Pleos 에뮬레이터 2.1.0 / Android 14 |
| 앱 ID | `kr.drivestep.tutor` |

저장소에는 **Android SDK·Pleos 이미지·AVD·APK·`local.properties`가 포함되지 않습니다.** 각자 개발 도구와 Pleos 실행 환경을 준비해야 합니다. 일반 휴대폰이나 일반 Android 에뮬레이터만으로 차량 SDK 연동을 검증할 수는 없습니다.

### Android Studio에서 실행

1. 저장소를 clone하고 프로젝트 루트의 `settings.gradle.kts`를 엽니다.
2. Gradle JDK를 17로 설정하고 Android SDK Platform 35 등 필요한 도구를 설치합니다.
3. SDK 경로를 설정한 뒤 Gradle Sync를 진행합니다. Pleos 의존성 다운로드가 안 되면 저장소 접근·아티팩트 제공 상태를 확인합니다.
4. 별도로 준비한 Pleos AVD를 시작합니다.
5. `app`의 `debug` 변형을 해당 에뮬레이터에 실행합니다.
6. 차량 콘솔에서 P·속도 0을 확인한 뒤 홈의 **도로를 보며 직접 연습 · 차로 변경**을 선택합니다.

### 명령행으로 실행

아래 예시의 JDK·SDK 경로와 AVD 이름을 자신의 환경에 맞춰 바꿉니다. `run-emulator.sh`는 준비된 AVD를 실행하며 이미지를 설치해 주지는 않습니다.

```bash
git clone https://github.com/Specters-of-the-Middle-Way/chageun.git
cd chageun

export JAVA_HOME="/path/to/jdk-17"
export ANDROID_HOME="/path/to/android-sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"

./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
DRIVESTEP_AVD="your-pleos-avd" ./scripts/run-emulator.sh
```

에뮬레이터 부팅 후 다른 터미널에서도 위 환경을 설정하고, 프로젝트 루트에서 실행합니다.

```bash
adb devices
# 여러 기기가 연결되어 있으면 실제 대상 serial로 지정
export ANDROID_SERIAL="emulator-5554"
./scripts/install.sh
```

macOS/Linux용 보조 스크립트입니다. Windows의 Gradle 실행은 `gradlew.bat`를 사용합니다. 기존 `scripts/launch-tutor.command`는 작성자의 macOS 개발 환경용이며, 파일 하나만 받아 모든 팀원의 컴퓨터에서 실행되는 설치 프로그램은 아닙니다. APK가 이미 있으면 재빌드하지 않으므로 소스를 수정했다면 먼저 빌드합니다.

### 짧은 시연 순서

1. **왼쪽 코스:** 반대 깜빡이를 한 번 켜 교정 음성을 보여주고, 올바른 신호·미러·조향·중앙·끄기로 완료합니다.
2. **옆 차량 코스:** 미러 속 옆 차량과 대기 안내를 보여주고, 차량이 앞으로 이동한 뒤 직접 차로를 바꿉니다.
3. **회고:** 방금 수행한 행동과 코치가 개입한 내용을 보여줍니다.
4. **SDK 실습:** 홈의 방향지시등 연습에서 에뮬레이터 차량 콘솔 조작이 SDK 수신으로 이어지는 것을 보여줍니다.

시뮬레이터에서는 **앱 내부 가상 버튼**을 사용합니다. SDK 실습에서는 **에뮬레이터 차량 콘솔 또는 debug 조작 패널**을 사용합니다. 화면 속 D·속도를 만들려고 실제 콘솔 기어·속도를 바꾸면 앱의 주행 제한이 적용될 수 있습니다.

## 8. 개발자가 먼저 볼 코드

아래 경로는 모두 저장소 루트 기준입니다.

| 파일 / 폴더 | 담당 역할 |
|---|---|
| `app/src/main/java/kr/drivestep/tutor/MainActivity.kt` | 홈·화면 전환, 음성 연결, 앱 수명주기 |
| `app/src/main/java/kr/drivestep/tutor/ParkedGate.kt` | 플랫폼의 정차 사용 제한 확인 |
| `simulator/DrivingSimulationSession.kt` | 가상 속도·차로·주변 차량·조작 순서·코치 개입 계산 |
| `simulator/CockpitRoadView.kt` | 같은 상태로 전방 도로·미러·가상 계기판 렌더링 |
| `simulator/DrivingSimulatorView.kt` | 화면 조작·시간 갱신·음성 요청·일시정지·회고 저장 |
| `contextcoach/SituationCoachEngine.kt` | 방향지시·속도 변화·경고에 대한 규칙 판단 |
| `vehicle/` | Pleos·AAOS 신호 읽기와 변경 구독 |
| `practice/`, `data/` | SDK 연습 상태 모델과 기록 저장 |
| `coach/VoiceCoach.kt` | TTS·번들 음성, 활성 상태·재생 처리 |
| `ride/`, `growth/`, `tutor/` | 기존 가상 연수·자세 설정·기초 학습 자료 |
| `docs/*-voice-cues.json`, `scripts/generate-voice-assets.py` | 음성 문구 목록과 번들 자산 생성 |
| `app/src/test/`, `scripts/verify-*.py` | 상태 모델 단위 테스트와 에뮬레이터 통합 검증 |

표의 `simulator/`부터 `tutor/`까지 생략된 경로의 앞에는 `app/src/main/java/kr/drivestep/tutor/`가 붙습니다.

```text
화면 조작 ─→ DrivingSimulationSession ─→ 스냅샷 ─→ CockpitRoadView
                        │                  └─→ 회고 저장
                        └─→ 코치 문구 ─→ VoiceCoach

차량 콘솔 ─→ Pleos / AAOS ─→ SDK 연습 모델 ─→ 피드백·조작 기록
```

두 입력 경로를 섞지 않는 것이 중요합니다. 새 시뮬레이터의 차량·차선은 앱 내부 상태이며, 기존 SDK 조작 연습의 실제 수신 기록과 구분합니다. SDK 조향 신호는 프로젝트에서 검토한 **전륜 조향각**으로 취급하며 핸들 회전 수라고 표시하지 않습니다.

## 9. 어디까지 검증했는가

다음은 2026년 11월 9일 v0.7 검증 기록에 남은 결과입니다. 이번 참고서 작성 과정에서 빌드·실차 시험을 새로 수행한 결과는 아닙니다.

| 검사 | 기록된 결과 |
|---|---|
| 빌드 | Debug APK, unsigned Release APK 생성 성공 |
| JVM 단위 테스트 | 148개 통과. 새 시뮬레이션 모델 25개 포함 |
| lint | 오류 0. 호환성·API·Canvas 할당 등의 경고는 남음 |
| 새 시뮬레이터 통합 검사 | 좌우 완료, 오조작 음성, 옆 차량 대기, 급가속, 중단·재개, 기록·재실행 확인 |
| 기존 코치 회귀 검사 | SDK 방향지시등, 출발·정지, 횡단보도, 주행 제한·회고 저장 확인 |
| 입력 분리 | 가상 조작 후 에뮬레이터 실제 차량 기어 P·속도 0 유지 확인 |
| 화면 | 에뮬레이터 전체 화면과 분할 앱 영역에서 배치 확인 |

음성 검증은 재생 시작 로그와 중단 상태를 확인한 것입니다. 모든 문구의 사람 청취 평가나 지연의 정밀 계측은 아닙니다. 실차, 다른 차종·해상도, 초보 운전자의 교육 효과는 추가 검증이 필요합니다.

```bash
# 기기 없이 실행
./gradlew :app:testDebugUnitTest :app:lintDebug

# 준비된 Pleos 에뮬레이터에 debug APK 설치 후 실행
python3 -u scripts/verify-simulator.py
python3 -u scripts/verify-coach.py
```

통합 검사에는 `adb`, 동작 중인 Pleos Virtual Console, Python의 `sqlite3.Connection.deserialize` 지원이 필요합니다. Python 환경에 따라 해당 API가 없을 수 있으므로 실행 전에 확인합니다.

통합 검사는 에뮬레이터 전용입니다. 차량 콘솔 상태를 바꾸고 연습 기록을 추가하며 검증 스크린샷을 갱신하므로 개인 실차에서 실행하지 않습니다. 가상 변수 화면의 별도 검증 도구는 `scripts/verify-situation.py`입니다.

## 10. 아직 구현하지 않은 것

| 후속 기능 | 먼저 확인할 조건 |
|---|---|
| 실제 주행 중 상황별 음성 코칭 | 대상 차종·앱 권한·주행 중 허용 범위·신호 지연·음성 우선순위 |
| 전방 영상·차선·주변 차량 인식 | 일반 앱에서 사용할 수 있는 데이터와 승인된 API |
| 내비 경로 연동·이전 실제 주행 비교 | 경로 데이터 접근, 위치·시간 정합, 비교 기준과 저장 방식 |
| 주차 궤적·핸들 회전 수 안내 | 차량 제원·조향 의미·주변 공간 데이터와 검증된 계산 모델 |
| 좁은 골목 교행·경사로 상황 판단 | 도로 폭·장애물·상대 차량·경사·진행 방향 정보 |
| 체격에 따른 시트·미러 자동 조절 | 차종별 조절 권한과 검증된 자세 모델 |

차량에 ADAS나 카메라 기능이 존재해도 일반 앱이 그 데이터에 접근할 수 있다는 뜻은 아닙니다. 기존 프로젝트 조사에서는 확보한 Vehicle SDK 2.3.2 범위의 전방 영상·차선·주변 객체 API를 확인하지 못했습니다. 새 SDK·차종에서의 지원 여부는 후속 검증 항목으로 남깁니다.

## 11. 다음 작업 제안

아래는 **아직 확정하지 않은 팀 논의용 제안**입니다. 현재 기능을 더 늘리기 전에 핵심 연습의 이해도와 차량 앱의 필요성을 먼저 확인하는 순서입니다.

| 순서 | 할 일 | 확인할 결과 |
|---|---|---|
| 1 | 팀원 각자 같은 버전을 실행 | 코스 진입·조작·회고까지 재현 가능 |
| 2 | 초보 운전자에게 가상 연습 사용 관찰 | 설명 없이 찾기 어려운 버튼, 음성이 늦거나 많은 순간, 조작 혼동 |
| 3 | 한 코스의 안내와 조작 방식 개선 | 도움 없이 수행한 단계와 반복 실수의 변화 |
| 4 | 교육 전문가와 코칭 내용 검토 | 잘못 학습할 표현·순서·생략 조건 수정 |
| 5 | 대상 실차와 허용 신호 조사 | 차종·연식·권한·신호 종류·수신 주기 목록 |
| 6 | 관찰 가능한 항목별 성장 기록 설계 | 조작 순서·반복 오류·도움 요청 등을 구분하고 전체 운전 능력으로 과장하지 않음 |

역할 분담은 기획·콘텐츠, 앱 UI·상태 모델, SDK·실차 확인, 테스트·사용자 검증으로 나눌 수 있습니다. 인원과 담당자는 팀에서 결정합니다.
