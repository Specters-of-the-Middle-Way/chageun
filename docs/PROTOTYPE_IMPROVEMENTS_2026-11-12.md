# 차근 프로토타입 기능·안정성 보완 결과

작업일: 2026-11-12 · 대상: 정차 상태에서 사용하는 차근 프로토타입

기준: [기획 재점검표](PLANNING_REAUDIT_2026-11-12.md), [앱 소개서](APP_INTRODUCTION_DRAFT_2026-11-12.md)

## 1. 결과와 범위

**이중 주차 시각 연습, D10·D11·D13의 추가 교통 상황, 공식 설명서 기능 두 개를 구현했다. 음성 연속 요청으로 새 재생이 취소되는 결함을 재현해 수정했다.** 빌드·단위 검사·Lint·에뮬레이터 검사를 실행하고 문서를 갱신했다.

간헐적인 음성 깨짐은 **원인 미확정**이다. 재생 생명주기 검사에서 사용자가 말한 음질 증상을 동일하게 재현·계측하지 못했다. 재생 완료 로그를 음질 정상의 증거로 사용하지 않는다. PC 메모리 여유와 에뮬레이터 부하를 별도로 기록했으나 인과관계를 확정하지 않았다.

기존 로컬 변경을 먼저 보존하고 그 위에 수정했다. 초기 변경 40개 파일의 목록, 패치와 복사본은 `.tooling/prototype-improvements-2026-11-12/baseline.json`, `before.patch`, `before-source.zip`에 보관했다. 초기부터 변경돼 있던 화면 정리 전체를 이번 작업의 새 성과로 계산하지 않는다. 커밋·푸시는 하지 않았다.

다음 조건을 유지했다.

- P·정차 조건, 출발 준비 확인, 화면 이탈·백그라운드 전환 시 중단, 직접 누르는 재개.
- 기록·차량 정보 사용 동의와 전기차 관련 교육의 조건부 표시.
- 큰 글씨, 좁은 화면 대응, 고정된 주요 버튼, 설명서 학습 단계 유지.
- 기존 PC 마이크 전달과 글레오 연속 대화 설정.
- 주행 중 글레오 대화, 백그라운드 자동 코칭, 실도로 AI 코스, 실제 ADAS·주변 센서 판단, 시스템 내비 수정, 실제 시트·미러·핸들·기어 제어는 추가하지 않음.

교육 보완만으로 원문이 요구한 실도로·실센서 기능의 등급을 올리지 않았다. 기획 점검표는 **구현 7 / 부분 16 / 미구현 5**를 유지한다.

### 이중 주차의 세 상황

기존 **상황별 교육 → 이중 주차 → 배치와 통행 연습**에서 연결한다.

1. **빈 정규 공간이 있는 상황:** 다른 차 앞에 세우면 출차 경로를 막는 그림과 이유를 보여 준다. 정규 공간을 선택하면 통로를 비운 배치를 보여 준다.
2. **정규 공간이 가득 찬 상황:** 보행·비상 통행 공간이나 다른 차 앞에 세우는 선택은 각각 다른 이유로 설명한다. 관리자와 이동·주차 위치를 조율하거나 다른 공간을 찾는 선택으로 진행한다.
3. **막힌 차가 출차를 요청한 상황:** 연락처만 남기기, 다른 사람이 밀 수 있다고 가정하기, 차주와 조율해 직접 이동하기를 구분한다. N단 유지·주차 브레이크 해제를 모든 차량에 공통으로 지시하지 않는다.

오답은 바로 수정하거나 해당 상황을 다시 시도할 수 있다. 완료 후 세 상황을 다시 선택해 이유를 복습할 수 있다. 기록 동의가 꺼져 있으면 저장 버튼이 비활성화되며, 동의가 켜진 경우에만 학습 완료를 로컬에 저장한다.

### 화면과 과제 판정의 일치

`TrafficScenarios`가 가상 객체의 종류·좌우 위치·앞뒤 위치·상대 속도·가림·통로 점유 상태를 만들고, `ScenarioSession`과 `ScenarioSurfaceView`가 같은 상태를 사용한다. 난수를 사용하지 않아 과제·상황 번호·경과 시간·가상 이동 거리가 같으면 재현된다.

- 동일한 7초 경과라도 자차 이동 거리가 다르면 접근 차의 위치와 진입 상태가 달라지는 단위 검사를 추가했다.
- D10·D13의 가림 상황은 120초를 기다려도 열리지 않는다. 가속을 계속해 가림 차량만 화면 밖으로 사라지는 일이 없도록 교육 구간 안에서 자차 이동을 제한한다.
- 통로가 막혀 있을 때의 주변 확인은 완료로 인정하지 않는다. 통로가 빈 뒤 새로 확인해야 한다. 일시정지·복귀 후에도 다시 확인한다.
- D11은 시간이 지나 보행자가 떠났다는 이유만으로 완료하지 않는다. 사용자의 정차 선택·새 주변 확인·후속 조작이 필요하다.
- 대기·취소는 실패·감점으로 기록하지 않는다. 선택한 상황과 이유를 완료/취소 화면, 관련 교육, 복습과 기록에 반영한다.
- 화면의 거리·속도·진입 판정은 **가상 연습 조건**이며 실제 진입 허가나 실차 안전 수치가 아니다.

## 4. 음성 진단: 확인된 결함과 미확정 음질을 분리

합성 문장은 다음으로 고정했다. 사용자 대화 원본이나 PC 마이크 녹음을 수집하지 않았다.

- 짧음: “주변을 직접 확인해 주세요.”
- 김: “이 안내는 정차한 상태에서 사용하는 가상 연습이에요. 옆 차로의 차량 위치와 통로를 확인하고 시야가 가려져 있으면 기다리거나 시도를 취소해 주세요.”
- 숫자: “현재 기온은 12.5도예요. 가상 연습의 거리는 30미터이고 속도는 시속 20킬로미터예요.”

기본 음성은 `coach_ride_red_wait.wav` 1.777초, `coach_signal_start.wav` 5.404초, `coach_signal_completed.wav` 7.595초다. 세 파일 모두 기존 22,050Hz·16bit·모노이며 파일이나 출력 음량을 바꾸지 않았다.

### 재현하고 수정한 앱 결함

수정 전 동일한 긴 문장을 12회 연속 요청하면 요청 번호가 12번 증가하고 SDK 초기화·중지·해제가 반복됐다. Pleos SDK의 비동기 중지 명령이 뒤늦게 도착해 **새 요청의 시작 전 `onStop`으로 취소되는 현상**을 재현했다. 실패한 검사와 로그를 그대로 보존했다.

수정 내용:

1. 동일한 대기/재생 중 요청은 병합한다. 수정 후 12회 입력의 요청 증가량은 **1**이다.
2. 고정 안내와 동적 TTS가 공유하는 출력 소유권을 도입했다. 이전 소유자의 늦은 해제가 새 출력의 소유권을 지우지 않는다.
3. 제출된 Pleos 출력만 중지하고, **중지 응답을 확인한 뒤** SDK 자원을 해제하고 다음 출력을 허용한다. 자연 완료나 아직 제출되지 않은 출력에는 불필요한 비동기 중지를 보내지 않는다.
4. 중지 확인 제한 시간은 정리 실패를 처리하기 위한 상한이다. 시간이 지났다는 이유로 새 음성을 재생하지 않는다. 확인 실패 시 예약 출력을 폐기하며 사용자 재요청이 필요하다.
5. 요청 번호가 다른 콜백, 화면 이탈 뒤 도착한 콜백을 무시한다. Android 초기화 실패 인스턴스도 해제한다.
6. 디버그 로그에 경로·출력 소유자·요청 번호·단조 시계 시각·시작/완료/취소·늦은 콜백·포커스·자원 해제를 남긴다. 합성 문장 원문 대신 길이를 기록한다.

수정 후 주 검사 로그에서 중지 응답 5회가 모두 확인됐으며 응답 없는 제한 시간 종료는 없었다. 이는 검사 조건의 결과이고 모든 엔진·환경에서 중지 응답이 온다는 보장은 아니다.

### 중단·복귀와 자원 확인

- 연속 입력, 다른 문장으로 교체, 음소거, 화면 비활성화·복귀, `close`, 포커스 상실을 검사했다.
- 경쟁하는 오디오 포커스 요청이 실제 허용됐고, 앱이 `FOCUS_CHANGE=-2`를 받아 재생을 취소한 뒤 `isSpeaking=false`가 됐다.
- 추가 재검사에서는 다른 기본 테스트 음성 파일을 실제 재생하며 포커스를 넘기고, 복귀만으로 이전 음성을 재생하지 않으며 **명시적으로 다시 요청하면 재생되는 흐름**을 확인했다. 검사 1개가 통과했으며 결과는 `final-focus-device.txt`에 있다.
- 화면 비활성 350ms 뒤 AudioFlinger에는 아직 CAAS 출력 트랙이 남아 있었으나 음량은 `-inf`로 음소거 상태였다. 1,250ms 뒤와 종료 후에는 해당 활성 출력 트랙이 없었다. ‘중지 즉시 모든 시스템 자원 소멸’로 과장하지 않는다.
- 기존 TTS 완료 → STT 준비, 동작 안내가 듣기를 중단하는 흐름, 비활성·종료 시 녹음 자원 해제 검사도 통과했다. 마이크가 열렸다는 사실만으로 실제 발화 인식 성공으로 계산하지 않는다.
- 실제 날씨와 글레오 요청이 가까운 시점의 검사는 **앱에 직접 요청을 전달한 검사**다. 글레오 서버의 최종 음성과 동시에 청취한 검사는 아니다.

### 실패 후 수정·재검사 이력

- **음성 수정 전:** 동일 문장 연속 요청 뒤 재생이 시작되지 않아 실패했다. 비동기 중지 명령의 경합을 수정하고 재검사했다.
- **첫 음성 수정 후:** Android 대체 TTS가 실제 합성될 것이라고 가정한 검사 하나가 실패했다. 이미지에서 초기화 불가임을 확인하고, 불가 상태의 명시적 안내·자원 해제를 검사하도록 수정했다. 대체 출력 성공으로 바꿔 적지 않았다.
- **첫 전체 UI 실행:** 완료 화면으로 바뀌는 순간 두 번 읽는 검사 조건의 경합, 백그라운드 복귀 때 기존 출발 준비 재확인을 건너뛴 검사 때문에 실패했다. 실제 앱의 준비 조건을 약화시키지 않고 검사에서 정상 UI로 다시 확인하도록 고쳤다. 전체 3개 재실행이 통과했다.
- **Lint:** 그림 그리기 중 객체 할당과 직접 문자열 조합을 정리했다. 코드로만 만드는 그림 View의 의도한 생성자에는 사유를 남겼다. 최종 Lint 0건이다.

실패 로그도 근거 폴더에 남겼다. 마지막 통과 결과와 구분한다.
