# 차근 글레오 연결 및 에뮬레이터 점검

점검일: 2026-11-12 · Windows / DriveStep_Pleos / Pleos Connect 2.1 / Android 14 · 앱 v0.10.0

> 이후 ‘함께하는 연수’ 대화 기능을 추가했다. 현재 공개 Schema에서는 출발 준비 확인을 `TALK_WITH_DRIVING_COACH`의 `PREPARATION` 요청으로 통합했다. 아래는 최초 세 기능 연결 당시의 검증 기록이며, 최신 대화 구현과 실제 음성 검증 범위는 [연수 대화 점검표](GLEO_CONVERSATION_2026-11-12.md)를 확인한다.

## 구현 범위

OpenAI 대화 실행 경로와 ‘AI 대화 사용’ 화면을 제거하고, 현대차 글레오의 Gleo Interface로 아래 세 기능을 연결했다. OpenAI API 키·중계 서버가 필요하지 않다. 글레오가 음성을 해석해 기능을 요청하며 차근이 기존 기능을 실행하고 결과를 반환한다. 기존 Pleos STT·TTS를 사용하는 ‘함께하는 연수’는 유지한다.

| 기능 | 말하기 예시 | 차근의 처리 |
|---|---|---|
| 출발 준비 확인 | 글레오, 차근으로 출발 준비 확인해 줘 | 운전 환경 9개·출발 확인 7개의 현재 확인 수, 동의한 차량의 신선한 벨트·경고 상태를 반환하고 준비 화면을 연다. |
| 날씨 운전 조언 | 글레오, 차근에서 날씨에 맞는 운전 조언 알려줘 | 기존 날씨 동의에 따라 현재 위치 또는 명시한 복정동 기준의 Open-Meteo 예보를 가져와 조언한다. |
| 주차 연습 시작 | 글레오, 차근으로 평행 주차 연습 시작해 줘 | 준비 항목을 직접 확인한 뒤 후진·평행·T자·전면 중 요청한 가상 연습을 시작한다. 생략 시 후진 주차다. |

실제 차량의 시트·핸들·기어를 제어하지 않는다. 준비가 부족하면 준비 화면으로 안내하고 `asking`을 반환한다. 진행 중인 연습을 새 요청으로 초기화하지 않는다. 체크리스트를 자동 완료하거나 실제 출발을 허가하지 않는다.

## 연결 방법과 데이터

- `app/src/main/assets/schema.json`에 세 기능과 호출명 ‘차근’을 선언했다.
- Manifest와 수신 코드가 공식 예시의 짧은 action 이름 및 현재 에뮬레이터가 실제로 보내는 `kr.drivestep.tutor.` 접두사가 붙은 이름을 모두 받는다.
- 현재 이미지의 글레오 호스트 `ai.umos.ambientai`에 공식 `APP_ACTION_RESPONSE` 응답을 보낸다. 다른 앱 전체로 차량 결과를 방송하지 않는다.
- P·정차·전경 사용이 가능할 때만 실행한다. 화면 이탈, 차량 상태 변경, 6초 시간 초과 때 취소하고 늦은 결과를 폐기한다. 공식 글레오의 7초 제한보다 먼저 종료한다.
- 응답에는 필요한 확인 수·벨트/경고 요약·날씨 조언·가상 코스만 담는다. 좌표·체격 프로필·대화/연수 기록은 글레오 응답에 넣지 않는다.
- 날씨 API에는 기존 동의와 위치 정밀도 제한을 적용한다. 위치를 얻지 못하면 ‘현재 위치 미확인 · 경기도 성남시 수정구 복정동 기준’을 표시한다. 날씨 실패를 맑음으로 추정하지 않는다.
- 글레오 호출로 앱이 열릴 때 자동 날씨 음성이 겹치지 않게 한다. 주차 시작은 앱의 연습 음성을 사용하므로 글레오 응답은 `silent`로 돌려준다.

## 마이크 문제와 해결

| 점검 | 발견 및 조치 |
|---|---|
| Windows 입력 장치 | 기본 입력이 Realtek 마이크이며 실제 입력 신호를 확인했다. 진단 녹음 파일은 저장하지 않았다. |
| Windows 마이크 권한 | 마이크 사용 허용이 이미 켜져 있었다. |
| Android 글레오 권한 | `RECORD_AUDIO`가 허용되어 있었다. |
| 에뮬레이터 실행 옵션 | 기존 실행 명령에 `-allow-host-audio`가 빠져 있었다. Windows 실행 스크립트에 추가하고 데이터를 지우지 않고 재시작했다. |
| 에뮬레이터 PC 마이크 전달 | 공식 로컬 제어 API의 `realAudioEnabled`가 `false`였다. `true`로 켜고 재확인했다. |
| 실제 발화 | 마이크 활성화 후 글레오가 발화를 인식하고 응답했다. 처음에는 앱 연결 오류가 나왔고, 아래 호출 형식을 수정한 뒤 세 기능에 반응하는 것을 사용자가 확인했다. |
| 호출 오류 | 로그에서 글레오가 `CHECK_DEPARTURE_READINESS`를 정확히 선택했으나 패키지명이 붙은 Intent를 받을 Activity가 없어 실패했다. 해당 이름을 수신하도록 수정하고 재설치한 뒤, 출발 준비 화면과 음성 답변이 나오는 것을 확인했다. |

다음 Windows 실행은 `scripts/start-pleos-windows.ps1`을 사용한다. 반응이 없으면 에뮬레이터의 **Extended controls → Microphone → Virtual microphone uses host audio input** 상태와 Windows 기본 입력 장치를 확인한다. 실행 옵션과 실제 전달 상태는 별도로 점검해야 한다.

## 검증 기록

앱에 Intent를 직접 보내는 검사와 사용자의 PC 마이크 실제 발화 확인을 구분했다. 직접 호출 검사는 글레오의 실제 발화 인식·자연어 판단 검사를 대신하지 않는다.

| 항목 | 결과 |
|---|---|
| APK 빌드·단위 검사·lint | 최종 빌드 성공, 단위 검사 373개 통과, lint 지적 0개. |
| 앱 기능 검사 | 실제 전달 형식으로 글레오 계측 검사 4개 통과. 세 기능, 잘못된 매개변수, 네 주차 코스, 실제 Open-Meteo 조회를 확인했다. 별도로 차량 동의 흐름 1개 통과. |
| 글레오 기능 목록 인식 | 실제 로그에 차근의 세 기능이 등록된 것을 확인했다. |
| 사용자 발화에서 기능 선택 | 글레오가 출발 준비 기능을 선택한 것을 확인했다. |
| 실제 발화: 출발 준비 | **사용자 확인 완료:** ‘화면이 열리고 답변도 나옴’. |
| 실제 발화: 날씨 조언 | **사용자 확인 완료:** ‘날씨 화면과 답변이 나옴’. |
| 실제 발화: 주차 요청 | **사용자 확인 완료:** ‘주차 연습 또는 준비 확인 안내가 나옴’. 응답 선택지가 두 정상 경로를 함께 포함하므로, 실제 음성으로 모든 준비를 마친 뒤 네 코스 각각을 시작했다는 의미는 아니다. |

빌드 근거는 `.tooling/gleo-build.log`, 실제 Intent 형식의 검사 근거는 `.tooling/gleo-device-qualified-final.log`의 `OK (4 tests)`, 차량 동의 검사는 `.tooling/gleo-device-installed-final.log`의 `OK (5 tests)`에 있다. 마지막 5개는 앞선 글레오 검사 4개와 차량 동의 검사 1개를 함께 실행한 결과이며, 중복 합산하지 않는다.

시험용 준비 완료 상태는 테스트 내부 메모리에서만 만들었다. 사용자 체크리스트를 완료로 저장하지 않았다. 테스트에서 변경한 동의·음성·날씨 설정은 복원한다.
