# 차근 외부 LLM 대화 — 로컬 개발판

> **보관 문서 — 2026-11-12:** 아래 내용은 이전 OpenAI 시험 경로의 기록입니다. 현재 앱에서는 이 요청 경로와 ‘AI 대화 사용’ 설정을 제거했습니다. 출발 준비·날씨 조언·주차 연습은 [글레오 연결 안내](GLEO_INTEGRATION_2026-11-12.md)를 따르세요. 이 기능을 위해 아래 API 키나 서버를 설정할 필요가 없습니다. 과거 비교용 클래스·서버 코드는 남아 있지만 현재 화면에서 호출되지 않습니다.

Pleos STT·TTS 3.3.1 ON_DEVICE는 유지합니다. 인식된 문장은 로컬 개발 서버를 거쳐 OpenAI Responses API에 전달하고, 응답은 앱에서 검증한 뒤 Pleos TTS로 읽습니다. Gleo Interface 연동은 아닙니다.

```text
Pleos STT 최종 문장
 → 차근: 최근 대화 + 자차 상태·측정값의 나이 + 내비 정보
 → Mac 로컬 중계 서버 → OpenAI Responses API
 → 구조화된 의도·상황·설명 → 앱의 방향 확인·안내 범위 검사
 → Pleos TTS → 자동 재청취 → 기록 동의가 있으면 연수 복습 저장
```

## API 키와 실행

1. `backend/.env.example`을 참고해 **backend/.env**를 작성합니다. 이 파일은 Git에서 제외됩니다. API 키를 채팅·APK·Git에 넣지 마세요.

   ```dotenv
   OPENAI_API_KEY=여기에_본인_API_키
   OPENAI_MODEL=gpt-5.4-mini
   OPENAI_REASONING_EFFORT=none
   ```

   기본 모델은 공식 문서에서 Responses와 Structured Outputs 지원을 확인한 `gpt-5.4-mini`입니다. 계정의 해당 모델 접근 권한·API 사용 한도를 확인하세요. 모델을 바꾸면 structured output과 reasoning 설정 호환성을 다시 확인해야 합니다.

2. 프로젝트 루트에서 서버를 실행합니다. Python 3.10 이상이며 외부 Python 패키지는 필요 없습니다.

   ```bash
   python3 backend/server.py
   ```

   서버는 **127.0.0.1:8765에만** 바인딩됩니다. 출력의 `key_configured=True`는 키 존재만 뜻하며, 유효성·사용 한도까지 확인했다는 의미가 아닙니다. `.env`를 변경했다면 서버를 다시 실행하세요. 환경 변수에 이미 설정한 값이 있으면 `.env`보다 우선합니다.

3. Pleos 에뮬레이터를 실행하고 다른 터미널에서 중계 포트를 연결합니다.

   ```bash
   .tooling/android-sdk/platform-tools/adb reverse tcp:8765 tcp:8765
   ```

   Windows나 별도로 설치한 Android SDK에서는 해당 SDK의 `adb`를 사용합니다. 에뮬레이터를 재시작하면 포트 연결도 다시 확인하세요.

4. 최신 Debug APK를 설치한 뒤 **함께하는 연수 → AI 대화 사용 → AI 대화 켜기 → 함께 시작하기**로 들어갑니다. 첫 안내 후 자동으로 듣습니다. 기존 차량 상태를 사용하려면 프로필의 차량 조작 신호 동의를 켜고 **차량 신호 연결**을 선택하세요.
5. “사이드미러를 봤는데 뭘 놓친 건지 모르겠어요”, “방금 얘기한 걸 조금 더 쉽게 설명해 줘”처럼 말합니다. 방향 관련 답변은 별도로 확인합니다. 표시되는 `OpenAI 응답`과 `기본 안내`를 구분해 주세요.

AI 대화를 끄면 외부 요청 없이 기존 튜터로 돌아갑니다. 키나 서버가 없으면 실패 이유를 표시하고 기본 안내를 사용합니다. 실제 OpenAI 응답이 없는 상태를 AI 답변 성공으로 표시하지 않습니다.

## 현재 구현 범위

- 자연어의 의도·방향·주변 상황 설명을 JSON으로 해석합니다. 운전자는 정해진 키워드만 사용할 필요가 없습니다.
- 현재 연수의 최근 **12개 대화 이벤트, 최대 2분**을 문맥으로 사용합니다. 일시 정지·재개·입력 출처 변경 이전의 대화는 제외합니다. 지난 연수 파일을 통째로 보내거나 장기 기억으로 사용하지 않습니다.
- 속도·방향지시등·기어·브레이크·앞바퀴 조향각을 채널별 측정 시점과 함께 전송합니다. **1.5초보다 오래된 차량·내비 값은 미확인 처리**합니다. 시연값은 `SIMULATION`, 실제 연결값은 `SDK`로 구분합니다.
- LLM이 의도와 설명을 제안해도 방향은 별도 확인을 거칩니다. 진입 가능 여부·차량 제어 요청은 기존 안내로 제한합니다. 자유로운 설명은 정차 중 교육 범위에 적용하고, 확인 중인 방향 질문은 LLM이 덮어쓰지 않습니다.
- 답변 대기 중 마이크를 다시 열지 않습니다. 응답이 오면 안내 후 다시 듣습니다. 새 조작 안내·새 요청·화면 이탈·대화 종료가 발생하면 이전 HTTP 요청을 취소하고 늦은 답변을 버립니다.
- 외부 서버 실패·키 누락·사용 한도·시간 초과·응답 형식 오류는 기본 튜터로 연결합니다. 앱 대기는 최대 10초이며 서버의 OpenAI 네트워크 대기는 8초입니다.
- 실제 적용한 AI 설명은 복습에 `AI 튜터 안내 · OpenAI`로 남깁니다. 시험 서버의 응답은 `시험 응답 · 실제 LLM 아님`으로 남깁니다. 입력이 시험 문장이면 계속 시험 문장으로 기록합니다. 완료 전에 취소된 LLM 요청의 발화는 최종 대화 이벤트로 저장하지 않습니다.

## 전송·보관과 한계

AI 대화 활성화는 기존 기록 저장 동의와 별개입니다. 활성화 시 현재 발화·선택된 최근 대화·차량 상태를 중계 서버와 OpenAI로 보냅니다. 음성 원본·GPS 좌표·신체 정보·이메일·전화번호·연수 파일은 자동으로 보내지 않습니다. 다만 사용자가 발화에 넣은 개인정보는 인식 문장에 포함될 수 있습니다.

중계 서버는 키를 응답으로 반환하지 않으며 요청 문장·응답·대화를 디스크나 로그에 저장하지 않습니다. OpenAI 요청에 `store:false`를 사용합니다. 이것이 제공자의 모든 보관 정책을 없애는 것은 아니며, API 악용 모니터링 보관 등은 계정의 데이터 정책을 따릅니다. 개발용 Pleos 서비스의 인식 로그는 앱의 저장 동의와 별개입니다.

프롬프트·구조화된 출력·로컬 필터는 모든 잘못된 설명을 차단한다는 보장이 아닙니다. 주변 차량 데이터가 없으므로 실제 진입 틈·주차 여유·차선 위치를 판단하지 않습니다. 기존 P·정차 게이트를 유지합니다.

**현재 HTTP 중계 연결은 Debug 앱의 에뮬레이터 개발 기능입니다.** Release 앱에서는 켤 수 없습니다. 공개 배포에는 인증된 HTTPS 서버, 사용자별 접근 제어·사용량 제한, 개인정보 처리 고지, 모델 응답 평가와 Pleos 심사가 추가로 필요합니다. 이 개발 서버를 `0.0.0.0`에 공개하거나 API 키를 앱에 옮기는 방식으로 배포하지 마세요.

## 키 없는 연결 시험

```bash
python3 -m unittest discover -s backend -v
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest
python3 scripts/verify-lesson.py
python3 scripts/verify-llm.py
```

`verify-llm.py`는 일시적인 **시험 응답 서버**를 만들고 `adb reverse`를 통해 실제 앱의 HTTP 연결을 검사합니다. 실제 차량 SDK 상태·이전 대화 전달, Pleos TTS 출력, 키 누락 오류, 지연 응답 취소, 저장·재실행 후 복습을 검사하고 설정을 원래대로 복원합니다. 기존 기록을 지우지 않고 시험 연수 1건을 추가합니다. 기록 20건이 이미 있다면 기존 기록을 밀어내지 않도록 검사를 건너뛰며 전체 통과로 보고하지 않습니다.

시험 서버는 자연어 모델이 아닙니다. **API 키 없는 자동 검사는 OpenAI의 실제 한국어 이해도·응답 지연·정확도를 입증하지 않습니다.** 키 설정 후 실제 목소리로 연속 대화, 부정·방향 정정, 설명 반복, 출력 도중 중단을 별도로 확인해야 합니다.

실행 결과 원문은 Git에서 제외되는 `docs/test-results/interactive-lesson-device.txt`, `docs/test-results/llm-fixture-device.txt`에 생성됩니다. 이번 Mac에서는 기존 생성 파일 접근 지연을 피하기 위해 Gradle 캐시와 빌드 출력만 `/tmp`로 분리한 뒤 검증된 APK를 기본 `app/build/outputs/apk/` 경로에도 복사했습니다. 소스·검사 항목은 동일합니다.
