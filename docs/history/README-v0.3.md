# 드라이브스텝 · 조작 실습과 상황별 음성 튜터

Pleos Vehicle SDK 2.3.2를 통해 **방향지시등 실습 → 실제 SDK 신호 수신 → 로컬 저장 → 기록 복습**을 연결한 첫 Android 앱입니다. 에뮬레이터용 디버그 버튼은 가상 차량에 입력을 보내며, 실습 완료는 SDK 수신값으로만 판정합니다. 실차 신호를 모의 데이터로 자동 대체하지 않습니다.

**v0.3.0 · 2026-11-08:** 앱 안에 에뮬레이터 조작 버튼을 넣고, **P·정지 상태 확인 → 조향 변경 신호 확인 → 음성 피드백 → 기록 복습**을 추가했습니다. 주차 설명·퀴즈는 별도 메뉴로 유지합니다. 실제 후진 이동·주차 경로·주차 성공 판정은 구현 범위에 포함하지 않습니다.

**처음 조작하는 방법**

1. **방향지시등:** 홈의 ‘조작법 보고 실습 시작’ → 조작법 확인 → ‘이제 방향지시등 실습하기’. 에뮬레이터에서는 오른쪽 패널의 **← 왼쪽 / 끄기 / 오른쪽 →**을 안내에 맞춰 누릅니다. 실차에서는 해당 차량의 물리 조작부를 사용합니다.
2. **기어·조향:** 홈의 ‘기어·조향 조작 확인’ → 필요한 경우 ‘차량 속도 읽기 허용’ → P·속도 0 확인 → ‘안내 확인 · 조작 실습 시작’. 에뮬레이터 패널에서 **−8° → 중앙 0° → +8° → 중앙 0°**를 순서대로 누릅니다. 반대 방향을 누르면 중앙으로 돌아와 다시 연습합니다.
3. **R·D 테스트 후 P 복귀:** 앱 사용이 제한되므로 PC에서 `python3 scripts/control-panel.py`를 실행하고 `http://127.0.0.1:8090/`의 P 버튼을 사용합니다. 다른 프로그램이 이 포트를 쓰면 종료하지 말고 스크립트의 포트 옵션을 이용합니다.
4. 실습 종료 후 홈의 **조향 기록 복습** 또는 **기록 복습**에서 확인합니다.

현재 에뮬레이터 콘솔과 SDK의 조향 부호가 반대라 앱의 좌우 시험 버튼에서만 입력 부호를 맞췄습니다. 실차 수신값은 그대로 사용합니다.

시험 버튼은 **debug 빌드 + Android 에뮬레이터**에서만 나타납니다. release 빌드에는 HTTP 제어 코드와 INTERNET 권한을 포함하지 않습니다. 에뮬레이터의 ±8 입력은 신호 확인용이며 실차 권장 각도가 아닙니다.

**이번 조향 실습의 정확한 범위**

- 기어 `GEAR_SELECTION`와 실제 속도 `PERF_VEHICLE_SPEED`는 AAOS, 조향각은 Pleos SDK로 읽습니다.
- Pleos 2.3.2 문서의 `SteeringWheelAngle`은 **앞바퀴 조향각**입니다. 핸들 회전각·회전 횟수로 해석하지 않습니다. 에뮬레이터 콘솔의 설명·범위와 SDK 문서 사이 불일치가 있어 실차에서 의미와 부호를 재검증해야 합니다.
- P, 사실상 0인 속도 신호, 유효한 조향 신호가 모두 필요합니다. UI 정차 허용 조건도 별도로 충족해야 합니다. 0.01m/s는 부동소수점 판정을 위한 오차 범위이며 움직여도 되는 권장 속도가 아닙니다.
- 중앙 준비는 0/4입니다. 이후 구독으로 들어온 **왼쪽 → 중앙 → 오른쪽 → 중앙** 변경만 네 동작으로 확인합니다. 초기 GET·중복값은 성공으로 세지 않습니다.
- 좌≤−5, 중앙±2, 우≥5라는 구간은 에뮬레이터 데모 인식 설정입니다. 실차 교육용 기준으로 검증되지 않았습니다.
- 필수 신호 수신이 5초 이상 끊기면 중단합니다. 연속 측정되는 속도는 원본 측정 시각도 검사하므로 오래된 GET 응답으로 유효 시간이 늘어나지 않습니다. ON_CHANGE 기어는 값이 유지될 수 있어 측정 시각의 나이만으로 차단하지 않습니다.
- 현재 에뮬레이터는 R·N·D에서 앱 UX 제한이 발생합니다. 제한을 우회하지 않으며, 실습 중 기어 변경·이동 신호·화면 이탈 시 중단합니다.
- 조향 기록은 AtomicFile JSON, 방향지시등은 SQLite에 저장합니다. 미완료 조향 기록도 재실행 시 중단 기록으로 복구합니다.

**지금 사용하기**

- **조작법 먼저 보기:** 레버형 차량의 조작 예시와 계기판 확인 방법을 음성으로 안내합니다. 차종 자동 식별 기능은 없으며 해당 차종 설명서가 우선입니다.
- **실습 시작:** 왼쪽으로 출발하는 상황과 오른쪽 골목으로 들어가는 상황을 정차한 채 연습합니다. 반대 방향이면 다정하게 다시 안내하고, SDK로 올바른 상태를 확인하면 칭찬합니다.
- **주차 순서 배우기:** 주변 확인 → 완전히 멈춘 뒤 후진 준비 → 계속 관찰 → 정렬 전 확인 → 주차 마무리, 다섯 상황을 설명과 질문으로 학습합니다. 이해 확인은 현재 과정에서만 유지되며 실제 주차 기록이나 숙련도 점수가 아닙니다.
- 상단 **음성 안내** 스위치와 **다시 듣기**로 재생을 조절합니다. 음소거 설정은 재실행 후에도 유지됩니다.

**이번에 구현한 기능**

- 차량의 정차 사용 가능 상태를 확인한 뒤 실습 시작.
- `꺼짐 → 왼쪽 → 꺼짐 → 오른쪽 → 꺼짐`의 다섯 관측으로 실습 완료.
- 시작 때 이미 켜진 방향지시등·중복 알림·GET 조회만으로 동작을 완료하지 않음.
- 잘못된 방향을 켜면 다시 끄고 해당 동작을 연습.
- SDK 오류·알 수 없는 신호·화면 이탈·주행 제한 발생 시 중단 기록 저장.
- SQLite에 조작 기록과 시간을 저장하고, 재실행 후 최근 기록·상세 복습·개별 삭제 제공.
- 앱이 강제 종료된 경우 미완료 기록을 다음 실행에서 중단 기록으로 복구.

실습 결과는 **방향지시등 조작 확인**입니다. 운전 실력·거울 확인·양보 판단을 평가하지 않습니다. SDK가 OFF/LEFT/RIGHT만 제공하므로 비상등이나 Blink/Flash의 차이를 이 앱이 감지한다고 주장하지 않습니다. 실제 도로 주행용 앱이 아니며 주행 중 사용을 허용하는 DO 선언도 넣지 않았습니다.

**실행 환경**

- JDK 17, Android SDK platform 35 / build-tools 35.0.0.
- Gradle 8.10.2 wrapper, Android Gradle Plugin 8.8.2, Kotlin 2.0.0.
- 앱 minSdk 28, targetSdk 34, compileSdk 35.
- **Pleos 전용** 에뮬레이터 2.1.0 / Android 14. 일반 휴대폰 에뮬레이터에는 Pleos 서비스가 없습니다.
- 프로젝트 `local.properties`에 SDK 경로를 지정합니다. Android Studio로 프로젝트를 열면 해당 컴퓨터의 경로로 설정할 수 있습니다.

이 작업 컴퓨터에는 `.tooling/` 아래에 Android 도구와 Pleos 이미지를 준비했습니다. 이 폴더와 `local.properties`는 소스 배포 대상에서 제외됩니다. 다른 컴퓨터에서는 [공식 설치 안내](https://document.pleos.ai/en/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator)에 따라 설치합니다.

**빌드와 실행**

프로젝트 폴더에서 실행합니다.

```bash
./scripts/build.sh
./scripts/run-emulator.sh
```

에뮬레이터 부팅이 끝나면 다른 터미널에서 실행합니다.

```bash
./scripts/install.sh
```

스크립트는 현재 컴퓨터의 JDK와 프로젝트 안 SDK를 사용하며 셸 설정 파일은 변경하지 않습니다. 다른 이름의 AVD는 `DRIVESTEP_AVD=이름 ./scripts/run-emulator.sh`로 실행합니다. 장치가 여러 개라면 `ANDROID_SERIAL`로 대상 에뮬레이터를 지정합니다. 이미 같은 AVD가 실행 중이면 다시 실행하지 않습니다.

빌드 APK: `app/build/outputs/apk/debug/app-debug.apk` (개발용 debug 서명).

**가상 콘솔로 직접 확인하기**

1. PC 브라우저에서 `http://127.0.0.1:8088/`을 엽니다. 연결이 안 되면 `adb forward tcp:8088 tcp:8088`을 실행합니다.
2. 콘솔의 기어를 P로 두고, 앱에 정차 실습 화면이 나타나는지 확인합니다.
3. **Emulation Controls**를 열고 검색창에 `Turn Signal`을 입력합니다. **Turn Signal State**의 Off를 선택합니다(Convenience 범주에서도 찾을 수 있습니다).
4. 앱에서 **조작법 보고 실습 시작 → 이제 방향지시등 실습하기**를 누릅니다. 최초 꺼짐 상태를 확인하면 왼쪽 안내가 나옵니다.
5. 콘솔에서 **Blink left → Off → Blink right → Off**를 차례로 선택합니다. 각 단계마다 앱의 다음 안내를 확인합니다.
6. 완료 화면의 다섯 관측과 시간을 확인합니다. 홈으로 돌아가 기록 복습을 열어봅니다.
7. 앱을 종료하고 다시 열어 기록이 유지되는지 확인합니다.

실습을 완료시키는 입력은 가상 콘솔이 Pleos 차량 서비스에 전달하고, 앱은 SDK 구독으로 수신합니다. 에뮬레이터에서 통과해도 실제 차량의 권한·신호 정확도·운전 교육 효과가 검증된 것은 아닙니다.

이 에뮬레이터는 방향지시등을 켜면 시스템 카메라 미리보기가 앱 위에 나타날 수 있습니다. 정차 상태에서 미리보기의 **×**를 누르면 안내를 볼 수 있습니다. 방향지시등을 끄면 미리보기도 사라집니다. 앱은 이 시스템 화면을 차단하지 않습니다. 화면 문구와 함께 음성으로 다음 동작을 안내합니다.

**음성 구현**

Android 한국어 TTS를 사용할 수 있으면 해당 엔진을 사용하고, 초기화·지원·재생 실패 시 앱에 포함된 한국어 WAV 45개를 재생합니다. 현재 Pleos 에뮬레이터에서는 기본 WAV 경로를 실제 확인했습니다. API 키나 서버 호출 없이 기본 안내가 작동합니다. 운전 상황을 LLM이 판단해서 만드는 음성이 아니라, 확인된 조작과 교육 단계에 연결한 고정 문구입니다.

새 안내가 오면 이전 안내를 대체하고, 음소거·다른 앱으로 이동·주행 제한·오디오 포커스 상실 때 중지합니다. 중단된 안내를 나중에 자동 재생하지 않습니다. 기본 WAV에는 200ms 시작 무음을 포함했습니다. 사용한 음성 자산 목록은 `docs/voice-assets.json`, 로컬 재생성 스크립트는 `scripts/generate-voice-assets.py`입니다(macOS의 설치된 Yuna 음성 사용, 개발 시연용 자산).

**테스트**

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
```

두 번째 명령은 Pleos 에뮬레이터가 실행 중일 때 사용합니다. 실습 상태 전이와 저장·재실행 복구를 각각 테스트합니다. v0.2의 검증과 제한은 [음성·상황 튜터 검증](docs/TUTOR_VALIDATION.md), 첫 버전 저장·복습 검증은 [v0.1 검증](docs/VALIDATION.md)을 참고하세요.

전체 연결 시험은 설치 후 `python3 scripts/verify-emulator.py`로 재현합니다(Python 3.11 이상, `sqlite3.deserialize` 지원 필요). 에뮬레이터만 대상으로 하며 실제 연습 기록을 추가합니다. 테스트 스크립트의 콘솔 HTTP 경로는 설치된 가상 콘솔에서 확인한 개발 시험용 구현이고, release 빌드에서는 사용하지 않으며 debug 에뮬레이터 패널에서만 사용합니다. 연결 테스트는 신호가 켜진 동안 시스템 카메라가 UI 조회를 가리는 문제 때문에 SDK 수신 후 저장된 실제 DB를 읽어 진행을 확인하고, 완료·재실행·복습은 화면에서도 확인합니다.

음성·상황 튜터 시험은 `python3 scripts/verify-tutor.py`로 실행합니다. 재생 로그와 Android의 실제 오디오 재생 상태, 음소거·다시 듣기, 오답·정답·다섯 단계 완료, 화면 이탈·주행 제한 때 중지를 확인합니다. 에뮬레이터에 연습 기록을 추가하고 시험 중 음성이 재생됩니다.
